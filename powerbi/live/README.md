# Live Power BI report (PBIP)

`RegulatoryMonitorLive.pbip` is a Power BI **project**: the semantic model is TMDL text and the report is PBIR JSON,
both generated by [`build_pbip.py`](build_pbip.py), so every measure, relationship and visual is reviewable in Git.

## Open it (first time, about 5 minutes)

1. Download the repo (**Code > Download ZIP**) and extract it, or `git clone` it.
2. Open `powerbi/live/RegulatoryMonitorLive.pbip` in Power BI Desktop (a version from 2025 or later, which reads PBIR).
3. Press **Refresh**. When asked how to connect to `https://raw.githubusercontent.com`, choose **Anonymous** and
   privacy level **Public**.
4. Optional: **Transform data > Edit parameters**:
   - `Dataset` = `bi_export` (synthetic year, every feature populated) or `data/live` (the real weekly monitor)
   - `Branch` = `main`
5. **File > Save as** a `.pbix` if you want a single file to share.

Every Monday after 07:17 Sydney the monitor commits a new run; press **Refresh** to load it.

## Pages

| Page | Answers | Visuals |
|---|---|---|
| Weekly briefing | What changed, what it costs, who does the work | 5 KPIs, plain-English takeaway, outstanding-changes table (days left coloured), cost by department, hours needed vs available |
| Capacity & sources | Can the team absorb the backlog; did every source answer | Load % heatmap (role × month), outstanding hours by role, backlog by target month, source health log |
| How to read this | Method, assumptions, limits | Text |

## Design system

Same tokens as the v1 report so the two read as one product: slate `#46586B` / ink `#1F2933` / lime `#B6D94C`,
page `#E6EAEE`; red `#C0392B` past target, amber `#D98C00` under 14 days. Sidebar, header banner, KPI tiles and panel
frames are drawn into the page backgrounds (`bg_live_*.png`) so visuals sit on top with no borders. Change the layout
in `PAGES` and the colours in `TOKENS`, then run `python powerbi/live/build_pbip.py`.

## If Desktop reports an error on open

The project is generated, not saved by Desktop, so a schema detail can differ between Desktop versions. The error names
the file and property; fix it in `build_pbip.py`, regenerate and reopen. `tests/test_powerbi_project.py` already checks
that every field a visual uses exists in the model and matches the CSV columns.
